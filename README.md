# Mario Lab · 马里奥强化学习实验平台

基于开源马里奥 PPO 项目开发的本地网页控制台，支持 **PPO / A2C 训练、关卡选择、实时训练画面、学习曲线、轨迹分析、模型恢复、独立评估与视频回放**。

本项目复用上游的游戏环境、预处理和 PPO 训练基础，补充前后端任务管理、数据采集及交互分析，并接入 A2C。上游本身已有模型观看、监控和录像工具；本项目重点是统一网页操作流程和补充实验管理功能。

## 1. Windows 安装与启动

### 首次安装或换电脑

1. 将完整工程解压到**纯英文路径**，例如 `D:\Mario_RL`，所有父目录也应避免中文。
2. 双击 **`安装.bat`**，等待依赖安装和游戏自检完成。首次安装需要联网；脚本会准备项目内的 Python 3.11，无需预装 Python、Node.js 或 Visual Studio。
3. 看到 `DOCTOR OK` 和 `SETUP OK` 后，双击 **`启动.bat`**。
4. 浏览器打开 [http://127.0.0.1:8000](http://127.0.0.1:8000)，确认顶部显示“本地服务在线”。

仓库已包含前端生产构建，一般使用不需要重新编译前端。

**不要直接搬运另一台电脑的虚拟环境。** 如果解压后的项目已带有 `.venv311`，可先改名备份，再运行安装脚本重新创建。模型与实验记录在 `data` 中，重装前请保留需要的数据；跨电脑迁移历史记录尚未完整验证。

### 使用 CUDA

默认安装 CPU 版 PyTorch，纯 CPU 电脑也能训练和演示。有支持 CUDA 的 NVIDIA 显卡时：

1. 安装合适的 NVIDIA 显卡驱动。
2. 关闭原服务，运行 **`安装CUDA.bat`**。
3. 安装完成后重新启动服务，在训练或评估配置中选择“自动检测”或“CUDA”。

仅在网页里选择 CUDA 不会自动安装 CUDA 版 PyTorch。CUDA 不可用时会回退 CPU；左下角跟随当前任务的**实际设备**显示，并在回退时明确提示。新任务初始化期间等待设备确认。更换运行环境后需要重启服务。

### 更新后启动

对正在运行的训练先执行“安全停止”，等待模型保存，再关闭原服务窗口。更新项目后重新运行 `启动.bat` 并刷新页面。新算法和关卡设置作用于新建任务，不能直接修改正在运行的训练。

### Linux / macOS

准备 Python 3.11 和系统 C++ 编译器后，在项目根目录执行：

```bash
python3.11 scripts/setup.py
.venv311/bin/python scripts/serve.py
```

这些平台未进行本次实机验收；当前已验证的运行路径为 Windows x64 + CPU。

## 2. 快速体验

### 观看已验证的 1-1 模型

进入“模型演示”，使用以下配置：

| 配置 | 设置 |
|---|---|
| 策略 checkpoint | 上游 PPO · Mario 1-1 |
| 游戏关卡 | 世界 1 · 第 1 关 |
| 评估回合 | 1 |
| 随机种子 | 42 |
| 单局环境步数上限 | 4000 |
| 策略采样 | 随机策略（按分布采样） |
| 评估设备 | CPU，用于复现已有验收条件 |

点击“启动独立评估”，可开启实时演示和 MP4 录制。本地验证中，此配置用 **329 个环境步**完成过一次通关。附带权重记录的累计训练量为 **8,050,000 个环境步**。

这是指定配置下的单回合结果，不代表所有种子、策略模式和运行环境下都能通关。确定性策略和随机策略的结果可能不同。

### 创建训练

点击右上角 **“算法与关卡设置 / 新建训练”**：

1. 选择 **PPO** 或 **A2C**。
2. 选择游戏关卡，填写名称、新增环境步数、设备和并行环境数等参数。
3. 选择从零开始，或加载**相同算法**的 checkpoint 继续训练。
4. 点击“启动真实训练”，到训练总览查看进度。

从零训练需要持续收集经验，短训练主要用于确认流程。选择预训练模型继续训练也不保证每局通关，参数更新可能带来表现波动。

## 3. 算法与关卡

### 算法选择

| 算法 | 训练实现 | 参数与权重 |
|---|---|---|
| PPO | Stable-Baselines3 PPO | 支持 rollout 长度、batch size、更新轮数和学习率等参数，可恢复附带 PPO 模型或本地 PPO 存档 |
| A2C | Stable-Baselines3 A2C | 使用自身更新流程，页面隐藏 PPO 专用的 batch size 和更新轮数，支持从零训练及恢复本地 A2C 存档 |

切换算法会清空已选起始权重，列表只显示同算法模型，后端也会校验。**PPO 和 A2C 的训练存档不能直接混用。** 评估时从模型文件识别算法，再调用相应加载器。旧版本项目生成的无算法标记模型按 PPO 处理。

目前支持 PPO 和 A2C。新增其他算法仍需适配训练入口、参数、模型加载和指标，不能直接选择任意算法名称。

### 关卡选择

训练和模型演示均可选择 **世界 1–8、每个世界第 1–4 关**。同算法模型可以在新关卡评估或继续训练，系统会使用新选择的关卡；跨关卡独立评估不修改原模型。

当前 CPU 实测覆盖 **1-1 和 1-2**，未逐关验收全部 32 关。部分关卡距离参考值为估计，通关仍以环境的 `flag_get` 信号为准。原模型能过 1-1，不代表能过新关卡；通常需要额外训练或微调。

自动评估采用**随机策略**，与模型演示默认模式一致。旧版本自动评估使用确定性策略，比较历史成绩时应注意这一差别。

## 4. 页面功能

### 训练总览

- **顶部统计**：累计环境步数、已完成回合、最远位置、近期独立评估通关率。
- **训练控制**：运行时间、交互速度、进度，以及暂停、继续和安全停止。暂停在安全训练边界生效，停止时保存模型。
- **实时环境预览**：显示训练 worker 0 的真实采样画面。默认目标 30 FPS，可切换 8 / 15 / 30 / 60 FPS 或关闭；实际帧率受采样、参数更新和电脑性能影响。
- **Agent 状态**：动作、世界坐标、当前回合奖励与步数、学习率、实际设备和可用的显存指标。
- **学习曲线**：平均回合奖励、探索进度、回合长度、独立评估通关率、策略 / 价值损失和策略熵。
- **日志和导出**：查看进程日志，导出原始指标。

环境步数表示 AI 与封装后游戏环境交互的次数，不等于原始 NES 帧数；回合数表示已结束的局数，死亡、通关或达到限制均可能结束一局。训练交互速度与画面显示 FPS 也是不同指标。

画面直接从模拟器读取，经后台 JPEG 编码和 WebSocket 传输，由浏览器连续更新图片。队列只保留最新画面以减少等待；关闭预览后训练仍继续，预览帧率不改变游戏动作定义或训练步数。

### 轨迹分析

- 从当前训练任务或独立评估中选择回合，支持成功 / 未通关筛选、Episode ID 搜索和分页。
- 最多同时比较 **4 条轨迹**，切换来源时保留已选路径。
- 以世界 X–Y 坐标绘制路径并标注终点，拖动时间轴查看某一步的位置、动作和奖励。
- 展示动作与逐步奖励曲线，帮助分析障碍前的决策。

轨迹回看展示的是坐标记录；原始录像在模型演示页单独录制和回放。

### 训练历史

展示本地实验名称、时间、算法、关卡、设备、累计步数、回合、最远位置和状态。点击“查看曲线”打开对应任务，配置按钮可查看参数与 checkpoint 信息。

### 模型演示

选择 PPO / A2C 模型、关卡、评估设备、回合数、随机种子、步数上限及策略模式，在独立进程中运行。支持实时画面、停止评估、MP4 录制 / 下载和历史结果回看。

独立评估不更新模型参数，也不增加训练任务的累计步数。页面可能同时显示历史记录的结果，新选择的配置在启动下一次评估后生效。

### 数据与设备状态

侧栏显示当前实验与状态，左下角显示所查看任务的实际设备，顶部显示本地服务连接状态。页面刷新或短暂断线后恢复记录，关闭浏览器不会停止训练。

实验摘要、指标、权重、轨迹、日志及视频保存在 `data`。模型恢复保留策略、优化器和匹配的奖励归一化统计，但不恢复游戏退出前的瞬间状态。结束使用时，先安全停止活动任务，再关闭服务。

## 5. 项目结构

```text
backend/app/              API、配置校验、设备检测、进程与 SQLite 存储
backend/training/         算法分派、训练评估、指标采集、画面传输
frontend/src/             React / TypeScript / ECharts 页面
frontend/dist/            已构建的前端，用于直接启动
scripts/                 安装、启动、模拟器构建与验证脚本
tests/                   接口及算法、关卡、设备配置测试
upstream/                保留的上游源码和预训练模型
vendor/                  Windows 模拟器安装包
examples/                已保存的演示样例
docs/                    来源说明、技术审查与验收记录
data/                    本地运行数据，不提交 Git
```

项目过程文档和汇报材料仅在本地保留，不提交到仓库。虚拟环境、临时验证文件、依赖目录和本地训练数据也由 `.gitignore` 排除。

- **11 项自动化测试通过**，覆盖原接口功能，以及算法匹配、关卡边界、配置传递和设备选择分支。

这些检查验证功能可运行，不代表训练出了新的稳定通关模型，也不构成 PPO 与 A2C 的性能对比。**真实 CUDA 训练、全部关卡和其他操作系统未完成本次实机验收。** 原验收材料见 [验收报告](docs/验收报告.md)。

## 7. 常见问题

**安装最后出现 `access violation reading 0x0000000000007FFC`**

先检查项目及父目录是否含中文。当前模拟器版本会错误转换部分非英文 ROM 路径，已用同一 ROM 的英文 / 中文路径对比复现。重新解压到 `D:\Mario_RL` 等纯英文路径，重建 `.venv311` 后运行 `安装.bat`。Gym 停止维护警告本身不是这次异常的原因。

**选择 CUDA 后仍显示 CPU**

以任务实际设备和日志为准。确认显卡支持 CUDA、驱动正常，并运行过 `安装CUDA.bat`。若 PyTorch 版本包含 `+cpu`，说明安装的是 CPU 版本。安装 CUDA 版本后重启服务；CUDA 不可用时显示 CPU 是实际回退结果。

**训练里不通关，演示却能通关**

训练持续更新参数，开局随机等待和随机状态也与演示不同；演示固定权重并按指定种子评估。应把训练存档放到相同关卡、种子、策略模式和步数限制下独立评估，再比较多回合结果。
